# 品質チェック 3 回目の指摘を直す（画面）

2026-11-19。Issue #133。指摘の本体は [docs/quality-review.md](../docs/quality-review.md) の F10・F11・F12。ここには、**直し方から学んだこと**を残す。

## 1. F10：古い応答が、新しい結果を上書きする（競合）

コメントを書く・消すたびに、一覧を読み直す。これが**続けて起きる**と、2 回の通信が飛ぶ。ところが、**応答が届く順番は、送った順とは限らない**。

```
1 回目を送る ─────────────────────→ （遅れて）古い結果が届く
2 回目を送る ───────→ 新しい結果が届く
                         ↑ 画面は新しくなる
                                          ↑ そのあと、古い結果で、上書きされる（間違い）
```

- **直し方**：読み直しのたびに、**番号札**（`useRef` の数）を進める。結果が届いたとき、**自分の番号が、最新のときだけ**、画面に反映する。古い番号の結果は、捨てる
- たとえ：病院の呼び出し。自分の番号より新しい番号が呼ばれていたら、古い呼び出しは、無視してよい
- **テストの作り方**：本物の競合は、タイミング次第で作りにくい。そこで、通信の答えを**こちらが手で返す**（`new Promise` の `resolve` を溜めておいて、**新しい方を先に、古い方をあとに**返す）。**順番を、わざと逆にできる**のがポイント

## 2. F11：ダイアログの名前は、見出しの文字から作られる

画面を読み上げる道具（スクリーンリーダー）は、ダイアログを「**見出しの文字**」という名前で呼ぶ。見出しの中に「閉じる」ボタンを入れていたので、名前が「**確認 閉じる**」になっていた（**実ブラウザで、そのとおりに確認できた**）。

- 直し方：「閉じる」ボタンを、見出しの**外**（右上に固定）へ。見出しは、「コメントを削除」「返信を削除」「投稿を削除」と、**何をするか分かる文字だけ**に
- 「確認」だけの見出しより、**何を消そうとしているかが分かる**ので、読み上げを使わない人にも、やさしい

## 3. F12：警告は、「開くとき」ではなく「閉じるとき」に出ていた

「削除のダイアログで、コンソールに aria-hidden の警告が出る」という指摘。最初、私は、**ダイアログを開くときだけ**を調べて、「出ない＝再現できない」と判断してしまった。ところが、ユーザーが、**キャンセルで閉じたとき**に黄色い警告が出るのを見つけて、教えてくれた。

| 操作 | 警告 |
|---|---|
| 開く | 出ない |
| **閉じる（キャンセル）** | **出る**（元のコードで、再現を確認） |

警告の中身：「`aria-hidden` の付いた `#root` の中の、押した『削除』ボタンに、フォーカスが残っている」。

**原因**：閉じるときに、MUI が、(1) 押したボタンへ**フォーカスを戻す** → (2) `#root` の `aria-hidden` を**外す**、の順で動く。(1) の時点では、まだ `#root` が隠れているので、ブラウザが「隠れている所に、フォーカスがある」と警告する。

**直し方**：
1. MUI の自動の「フォーカスを戻す」を止める（`disableRestoreFocus`）
2. **ダイアログが閉じ終わってから**（`onExited`）、開く前にフォーカスのあったボタンへ、**自分で戻す**（フック `useRestoreFocusOnClose`）

フォーカスを戻すこと自体は、キーボードで操作する人が位置を見失わないために、**大事**なので、なくさない（戻す**タイミング**を、後ろにずらす）。

**直したあとの確認（実ブラウザ）**：コメント削除・投稿削除・投稿の編集の 3 つのダイアログで、開いて「キャンセル」で閉じても、警告 0 件。フォーカスは、押したボタンに戻る。

### この件の学び
- **「再現できない」と言う前に、操作を変えて試す**（開く・閉じる・保存する…）。今回は、「閉じる」を試していなかった
- **ユーザーの見た物は、大事な情報**。私の Chrome で出なかったから、と終わらせず、「どの操作で出ましたか？」を聞くと、早い
- 試しに足した `autoFocus`（「キャンセル」に最初からフォーカス）は、**テスト（jsdom）では効いたのに、実ブラウザでは効かなかった**（フォーカスは、ダイアログの枠に行った）。**効かないコードは、誤解のもとなので外した**
- **テスト用の偽のブラウザ（jsdom）と、本物のブラウザは、フォーカスの動きが違う**。警告そのものは jsdom では出ないので、**本物のブラウザで確かめる**（Chrome DevTools の MCP で、画面の状態と、コンソールを見られる）。テストでは、「フォーカスが戻ること」を守る

## 4. 道具の「成功」を疑う：わざと外して確かめる

フォーカスのテストは、**フックの「戻す」処理を一度外して、テストが失敗することを確かめた**（2 件が失敗。確認後、戻した）。外しても成功するなら、そのテストは、何も見張っていない。

**ただし、テストが成功することと、本物のブラウザで警告が消えることは、別**。両方を確かめた（テスト 126 件の成功と、実ブラウザのコンソール 0 件）。
