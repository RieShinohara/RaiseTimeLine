# コメントの API：返信（自分の表を指す）、連鎖して消す、権限の判断

2026-11-18。⑥-3（Issue #119）。コメント・返信・削除・コメント数。いいねと同じ「まとめて数える」を、もう一度使った。

## 1. N+1 の予想と結果
一覧（投稿 20 件）に「コメント数」を足すとき、素直に作ると **1 + 20 = 21 回**（自分の予想のとおり。N は「投稿の数」）。まとめて聞くと、いいねと合わせて、ログイン中 **4 回**・ログインなし **3 回**（件数によらず一定。`PostSqlCountTests` で確認）。

## 2. 作ったもの
| 部品 | 役割 |
|---|---|
| `V5__create_comments.sql` | `comments` 表。返信先 `parent_comment_id` が、**同じ表の `id` を指す** |
| `CommentMapper` | コメントの SQL（追加・投稿ごとの一覧・1 件・数える・まとめて数える・削除） |
| `CommentService` | 入れ子の組み立て、返信先の確認、削除の権限の判断 |
| `CommentController` | `GET`・`POST` `/api/posts/{postId}/comments`、`DELETE` `/api/comments/{id}` |
| `PostService`・`PostController` | 一覧に `commentCount`、`GET /api/posts/{id}`（詳細画面用）を足した |

## 3. 学んだこと
### 自分の表を指す（自己参照）
- 返信は、別の表ではなく、**同じ `comments` 表の行**。「どのコメントへの返信か」を `parent_comment_id` に入れる。コメントそのものは空（NULL）
- 1 段だけにするため、返信先が返信だったら、**その元のコメントの返信に付け替えて**保存する（`CommentService.create`）

### 連鎖して消す（`ON DELETE CASCADE`）
- `parent_comment_id` に `ON DELETE CASCADE` を付けたので、**親コメントを消すと、DB が返信も消す**。Java で「返信を探して 1 件ずつ消す」コードは要らない（CMT-1c）
- 投稿を消したときも、同じ仕組みで、コメント・返信・いいねが消える（POST-2）

### 入れ子は 1 回の SQL で
- コメントと返信を、`post_id` で**まとめて 1 回**読み、Java 側で「親 → 返信の一覧」に組み立てる（返信ごとに SQL を打つと N+1）
- 並びは `ORDER BY id`（古い順。id は増える番号）

### 権限の判断（401・403・404）
- ログインなし → 401（ルール表）／他人のコメントを、投稿の持ち主でもないのに消す → **403**（Service）／存在しない → 404
- 削除できるのは、**書いた人と、投稿をした人**（CMT-3）。「投稿の持ち主」は、コメントの `post_id` から投稿を引いて調べる
- **確認のあとに投稿が消された**場合は、外部キーの制約が止める → `DataIntegrityViolationException` を 404 に直す（投稿の編集の B8 と同じ考え方）
