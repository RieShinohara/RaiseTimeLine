# 品質チェック 3 回目の指摘を直す（バックエンド）

2026-11-19。Issue #131。指摘の本体は [docs/quality-review.md](../docs/quality-review.md) の B11・B12・B13。ここには、**直し方から学んだこと**を残す。

## 1. 直す前に、テストが「失敗する」ことを確かめる

3 つとも、**先にテストを書いて、直す前に動かした**。5 件が失敗し、理由も指摘のとおりだった。

| 指摘 | 直す前の失敗の理由 |
|---|---|
| B11 | 「404 の ApiException」のはずが、DB のエラーがそのまま出た |
| B12 | 応答に `$.message` がなかった（標準の形だった） |
| B13 | 仮のユーザー管理（`InMemoryUserDetailsManager`）が、自動で作られていた |

**なぜ先に失敗させるのか**：テストが「いつも成功する」物（空振り）だと、直しても直さなくても成功して、守りにならない。**直す前に失敗 → 直したら成功**を見て、初めて「このテストは、この問題を見張っている」と言える。

なお、コメント側の同じ処理（`CommentService.create` の try/catch）は、**直す前から成功した**。以前から直してあったが、テストがなかったので、今回、足した。

## 2. B11：「確かめる」と「する」の隙間を、DB の制約が止める

```
1. 投稿があるか確かめる   ← 「ある」
   （この間に、別の人が投稿を消す）
2. いいねを入れる         ← もう、ない。DB の外部キーが「親がない」と止める → 例外
```

- **隙間そのものは、なくせない**（確かめてから入れる、の間には、必ず時間がある）
- でも、**DB の外部キーが、最後の砦**として、おかしなデータが入るのを止めてくれる
- 止まったときの**例外を、利用者に分かる形（404）に直す**のが、アプリの仕事。直さないと、500（サーバーの故障）に見える

テストでは、本物の DB を使わず、**Mapper を偽物（Mockito の mock）にして**、「確かめるときは『ある』、入れるときは『外部キー違反』」という状況を、**わざと作った**。本物の競合は、タイミングの問題で、テストでは作りにくい。

## 3. B12：エラーの形を 1 か所でそろえる（`@RestControllerAdvice`）

画面は、エラーの本文から `{"message": "..."}` の `message` を取り出して表示する。ところが、Spring が**自分で作る**エラー（壊れた JSON、`/api/posts/abc`）は、標準の形（`timestamp`・`status`・`error`・`path`）で、`message` がない。

- `ApiExceptionHandler`（`@RestControllerAdvice`）は、「どこで起きた例外でも、ここで受けて、同じ形で返す」受付係
- 受ける例外を足す（`HttpMessageNotReadableException`＝読めない入力、`MethodArgumentTypeMismatchException`＝型の違い）と、形がそろう
- **形がそろっていると、画面は、1 通りの読み方で済む**

見つけた経緯：品質チェックで、`curl` で壊れた JSON を送って、**実際に確かめた**。読んだだけでは「未確認」だった指摘が、動かして「確認」になった（[ノート 16](16-quality-check-3.md)）。

## 4. B13：「使わない部品」でも、定義しないと、Spring が勝手に作る

起動のたびに出ていた `Using generated security password` は、**ユーザーを決める部品（`UserDetailsService`）がない**ので、Spring が「とりあえず」仮のユーザー（`user`）とランダムなパスワードを作っていた、という意味。このアプリは JWT で認証するので、使われない。

- **直し方**：「どの名前も、見つからない」と答える部品を、自分で定義した。ログインは `AuthService` が自前で行うので、この部品は呼ばれない
- **なぜ、この方法か**：Spring Security の公式の推奨。もう 1 つの方法（自動設定を除外する）は、Spring Boot 4 で、クラスの置き場所が変わっていて、名前を間違えると**黙って効かない**恐れがある
- **たとえ**：受付に誰も置かないと、建物が「とりあえずの仮の受付係」を自動で雇ってしまう。「この建物は、別の入口で受け付けます」と書いた**名札だけの係**を置いておけば、勝手に雇われない
