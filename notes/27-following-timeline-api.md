# 「フォロー中」タイムラインの API

2026-11-22。Issue #153。タイムライン（機能定義書 04）の 2 つ目。講義にはなかったので、これまでの部品（投稿の一覧、フォロー表、いいね・コメント数のまとめ読み）を組み合わせて作った。

## 1. 作った API（2 つ）

| メソッド | パス | 返す物 |
|---|---|---|
| GET | `/api/posts/following?before=&size=` | **自分がフォローしている人**の投稿（新しい順）。形は `/api/posts` と同じ |
| GET | `/api/posts/following/new-count?after=` | `after` より新しい、フォロー中の人の投稿の件数 |

- **ログインが必要**（なければ 401）。「全体」は、ログインなしで見られる（TL-3）
- 自分の投稿は入らない（自分自身はフォローできない。DB の CHECK 制約）

## 2. 宛先を分けた理由（案 A）
「窓口を分ける（`/api/posts/following`）」か「同じ窓口にメモを付ける（`/api/posts?feed=following`）」かを比べて、**窓口を分けた**。

- 窓口が別だと、「この窓口はログイン必須」を、入口のルール表（`SecurityConfig`）に **1 行で**書ける。プログラムの中に「ログインしているか」の確認を、自分で書かなくてよい（書き忘れの心配が減る）
- プロフィールの投稿一覧（`/api/users/{username}/posts`）と、同じ流儀

## 3. つまずきかけた所：ルール表は「上から順に当てはめる」
ルール表には、すでに `GET /api/posts/{id}`（ログインなしで可）がある。`{id}` の部分には**どんな文字も当てはまる**ので、`/api/posts/following` の「following」も、`{id}` として**ログインなしで通ってしまう**。

- 対策：「`/api/posts/following` はログイン必須」の行を、**`{id}` の行より先に**書く（ルール表は、上から順に当てはめて、最初に合った行で決まる）
- 確かめ方：その行を消して、テストを動かした。**「ログインしていないと見られない」のテストが落ちた**（穴は、本当に空いていた）。戻すと緑
- Controller 側は、`/following`（決まった文字）が `/{id}`（何でも当てはまる）より**先に選ばれる**ので、問題ない（`/new-count` と同じ）

## 4. SQL（JOIN で、フォローに絞る）
```
FROM posts p
JOIN users u   ON u.id = p.user_id
JOIN follows f ON f.followee_id = p.user_id AND f.follower_id = 自分
```
- `follows` の 1 行は「follower が followee をフォローしている」（ノート 23）。**自分が follower の行**と、**投稿の持ち主が followee の行**をつなぐと、「自分がフォローしている人の投稿」だけが残る
- `follows` の主キーは `(follower_id, followee_id)`。「自分がフォローしている人」の検索に、その索引が効く
- 数・「押したか」・コメント数は、既存の `toPage` を使い回して、まとめ読み。SQL は **4 回**（投稿 1 ＋ いいね数 1 ＋ 押したか 1 ＋ コメント数 1。件数によらず一定）

## 5. テスト（10 件）と、わざと壊す確認
- 401（2 本）／フォローした人だけ・新しい順・自分の投稿は入らない／空のとき／フォロー解除で消える／`before`・`hasNext`／`size` の範囲外／いいね・コメント数／新着の件数／`after` の不正／SQL の回数
- **わざと壊して、1 回に 1 か所ずつ確かめた**
  1. ルール表の新しい行を消す → 401 のテストだけが落ちた
  2. JOIN の「自分がフォローしている」の条件を外す → 3 件が落ちた
- **気づき：最初のテストは、壊しを見逃した。** 「フォローしていない人」を、**誰からもフォローされていない人**にしていた。条件を外しても、その人の投稿は、もともと JOIN に出てこないので、テストが通ってしまった。**別の人にフォローされている人**に変えると、壊しを見つけられた。**テストの相手役は、「間違った実装でも、通ってしまう人」ではなく、「間違った実装なら、混ざってしまう人」にする**
