# ユーザー検索の API

2026-11-22。Issue #157。機能定義書 08。講義 31 の内容（ユーザー名で探す）に、表示名でも探せる、を足した形で作った。

## 1. 作った API
`GET /api/users?q=山田&size=20`（ログイン不要）。ユーザー名か表示名に「山田」を含む人を、ユーザー名の順に返す。応答の形は、フォロー・フォロワーの一覧と同じ（`{ users, hasNext }`。メールは出さない）。

## 2. 宛先の決め方：`/api/users?q=` と `/api/users/search?q=`
- `/api/users?q=` は「ユーザー全員の名簿を、`q` で**絞り込む**」。`/api/users/search` は「`search` という専用の窓口」
- すでに `/api/users/{username}`（ユーザー 1 人の窓口）がある。ユーザー名は英数字 2〜30 文字なら自由なので、**「search」という名前のユーザー**も作れる。`/api/users/search` は、その人のプロフィールの窓口と、**同じ見た目**になって、区別がつかない
- そこで、名簿の窓口に絞り込みを付ける形にした（衝突しない）

## 3. いちばんの落とし穴：`LIKE` の `%` と `_`
`LIKE` は「〜を含む」を探す仕組みだが、**2 つの記号に特別な意味**がある。

| 記号 | LIKE での意味 | 困ること |
|---|---|---|
| `%` | 何文字でも | 「100%」と入力すると、「100abc」まで当てはまる |
| `_` | 任意の 1 文字 | 「a_b」と入力すると、「axb」まで当てはまる |

ユーザー名には `_` が使える。**入力した文字を、そのまま検索に使うと、他の人が混ざる。**

- 対策：入力の中の `\`・`%`・`_` の前に `\` を付けて、「ただの文字」にする。SQL 側には `ESCAPE '\'`（「`\` は、その目印です」という宣言）を書く
- **`\` を最初に直す**（あとにすると、`%` や `_` の前に付けた `\` まで、二重に直してしまう）
- Java で `%入力%` の形（「入力を含む」）にして、1 つの値として SQL に渡す

### SQL インジェクションとの違い（復習）
- **SQL インジェクション**：入力が SQL の**文**として読まれてしまう（`'; DROP TABLE users; --`）。`#{}`（穴あきの注文票）で、値は値として渡すので起きない。`${}` は、文字をそのまま SQL に貼るので、使わない
- **LIKE の記号**：値として渡しても、`LIKE` の**中で**、記号が特別に扱われる。別の問題なので、別の対策（エスケープ）が要る
- 両方を、テストで確かめた（`' OR 1=1 --` などを入れても、全員は出ない・表は消えない）

## 4. `ILIKE` と、並び順
- `ILIKE` は、PostgreSQL の「大文字小文字を区別しない `LIKE`」（SRCH-1）
- 並びは `ORDER BY lower(username), id`（大文字小文字を無視。同じなら id で、毎回同じ順にする）
- 1 件多く読んで、`hasNext` を決める（投稿・フォロー一覧と同じ）

## 5. 作りのポイント
- **取り出す列を、明示する**：`id・username・display_name・bio` だけ（メール・ハッシュは、そもそも取り出さない）
- **入力の確認**：前後の空白（全角も。`strip()`）を取る。空は 400、50 文字超は 400
- 「フォロー済みか」は、まとめて 1 回（`findFolloweeIds`。N+1 を避ける）。SQL は、ログイン中 2 回・ログインなし 1 回
- 層の決まり：`search/` に Controller・Service を作り、DB は `UserMapper`・`FollowMapper` を呼ぶ（Controller は Mapper を直接呼ばない）

## 6. テスト（15 件）と、わざと壊す確認
- 部分一致（ユーザー名・表示名の日本語）／大文字小文字／`_`・`%`・`\` を文字として探す／順番／`size`・`hasNext`／空白を取る／400（空・長すぎ・`size`）／該当なし／`followedByMe`／メールが出ない／SQL インジェクション風の入力／SQL の回数
- **わざと壊して、1 回に 1 か所**
  1. エスケープを外す → `_`・`%`・`\` の 3 件だけが失敗（他の人が混ざることを確認）
  2. `ILIKE` を `LIKE` にする → 「大文字小文字は区別しない」の 1 件だけが失敗
  3. 表示名の条件を外す → 表示名で探す 3 件が失敗
- **工夫**：他のテストの人と混ざらないよう、毎回ちがう「目印の文字」を、名前に入れて探した（テストの DB は、全テストで共有しているため）
