# 品質チェック（3 回目）：いいね・コメントの点検

2026-11-19。記録の本体は [docs/quality-review.md](../docs/quality-review.md) の「3回目」。ここには、**やり方から学んだこと**を残す。

## 1. 「読んで見つけたこと」と「動かして確かめたこと」を分ける

今回は、読む役を 3 つに分けて（バックエンド・画面・文書）、報告をもらった。報告は**そのまま信じず**、大事な指摘は、自分でコードを読み直して確かめた。

| 報告の言葉 | 意味 | 記録での扱い |
|---|---|---|
| 確認して問題なし（根拠：ファイル:行） | コードを読んで、問題がなかった | 「良かった点」 |
| 未確認 | 読んだ範囲では、そう見えるが、動かしていない | 「読んで見つけた。**再現していない**」と書く |
| 動かして確認 | 実際に動かして、結果を見た | 「動かして確かめたこと」 |

例：「壊れた JSON を送ると、応答の形が違うかもしれない」は、最初は**未確認**だった。`curl` で送ると、実際に **400 だが形が違う**と分かり、「動かして確認」に変わった。**読むだけでは、確かさが足りない。動かすと、確かになる。**

## 2. 認可は、`curl` で確かめる（401・403・404 の使い分け）

| 状態 | 意味 | 今回の確認 |
|---|---|---|
| 401 | 札がない・間違い（誰か分からない） | 札なしで、コメント・いいねをすると 401 |
| 403 | 誰かは分かるが、してはいけない | 関係のない人が、他人のコメントを消すと 403 |
| 404 | その物がない | 存在しない投稿・コメント |

**403 を確かめるには、3 人目が要る。** 「書いた人」「投稿の持ち主」は、どちらも消せるので、2 人だけだと、どちらかが当てはまってしまう。**どちらでもない人**（3 人目）で、初めて 403 が出る。

## 3. 「見えない」と「消えた」は違う（連鎖削除）

投稿を消したあとに、その投稿のコメントを取りにいくと 404 になる。でも、これは「投稿がないから」で、**コメントの行が DB から消えた証拠ではない**。

そこで、DB の中を直接数えた（`select count(*) from comments where post_id = …`）。**0 件**だったので、`ON DELETE CASCADE`（親を消すと、子も自動で消える）が、本当に働いていると分かった。

たとえ：家を取り壊した（投稿を消した）あと、「その家宛ての郵便が届かない」だけでは、郵便局の台帳から消えたとは言えない。**台帳（DB）を見て、初めて確かめられる。**

## 4. 起動ログの警告を読む

起動のたびに出ていた `Using generated security password` は、「ユーザーを決める部品が無いので、仮のユーザーとパスワードを、自動で作った」という意味。このアプリは JWT で認証するので、使われない。**動作には影響しないが、警告が出続けると、本当に大事な警告を見落とす。**

- 「動いているから、いい」ではなく、「**なぜ出るか**を説明できる」ところまで読む
- 直し方は 2 つ：①ユーザーを決める部品を自分で定義する（公式の推奨）／②自動設定を除外する

## 5. 競合：「確かめる」と「する」の間

B8（投稿の更新）と B11（いいね）は、同じ形の弱点。

```
1. 投稿があるか確かめる   ← ここで「ある」
   （この間に、別の人が投稿を消す）
2. いいねを入れる         ← もう、投稿がない → エラー
```

たとえ：「席が空いているのを見て、座ろうとしたら、その一瞬に他の人が座った」。**「確かめる」と「する」を、1 つの操作にまとめる**（SQL の条件に入れる）か、**失敗を受けて、きちんと 404 にする**のが対策。

画面側にも、似た形がある（F10）。**書いたあとの読み直し**が 2 回重なると、**古い応答があとから届いて、新しい一覧を上書き**しうる。対策は、**読み直しに連番を付けて、最後の 1 回だけを反映する**。

## 6. 画面の「名前」：見出しの中に、ボタンを入れない

画面の読み上げ（スクリーンリーダー）は、ダイアログの名前を、**見出しの文字**から作る。見出しの中に「閉じる」ボタンを入れると、名前が「確認 閉じる」になる。**ボタンは、見出しの外に出す。**

また、いいねボタンは、名前を「いいねする」→「取り消す」と切り替えながら、`aria-pressed`（押されている状態）も付けると、**状態が二重に伝わる**。どちらか 1 つにする。

## 7. 空振りを疑う

- lint は、わざと悪いコードを書いて、**2 件を指摘して失敗するか**を確かめた（確認後、消した）
- リンク切れの確認は、187 本で 0 件。2 回目に、存在しないリンクで検出できることを確かめてある
- 警告（`500 kB を超える塊`）は、エラーではないので、見落としやすい。出力を最後まで読む
