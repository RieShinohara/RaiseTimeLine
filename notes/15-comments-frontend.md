# コメントの画面：投稿の詳細画面（URL の引数、共用の部品、書いたあとに読み直す）

2026-11-18。⑥-4（Issue #121・#123）。投稿カードにコメント数を出し、押すと詳細画面（`/posts/:id`）でコメント・返信を見る・書く・消す。

## 1. 作ったもの
| 部品 | 役割 |
|---|---|
| `api/comments.ts` | コメントの API を呼ぶ関数（一覧・書く・消す）と、返事の型 |
| `comments/usePostDetail.ts` | 投稿とコメント一覧を、**同時に**読む（`Promise.all`）。書いたあとの読み直し |
| `pages/PostDetailPage.tsx` | 画面の全体。URL の `:id` を読む（`useParams`） |
| `components/CommentForm.tsx` | 入力欄。**コメントと返信で、同じ部品を使い回す** |
| `components/CommentThread.tsx` | コメント 1 件と、その返信 |
| `components/DeleteCommentDialog.tsx` | 削除の確認（返信付きは文言が変わる） |
| `PostCard.tsx` | コメント数を、詳細画面を開くボタンにする（`onOpenComments`） |

## 2. 学んだこと
### URL の中の番号を読む（`useParams`）
`/posts/39` の `39` は、文字として届く。`Number(id)` で数にする。別の投稿の URL に変わっても、画面の部品は同じものが使い回されるので、**`key={id}` を付けて、作り直す**（前の投稿の状態が残らないように）。

### 書いたあとは、一覧を「読み直す」
コメントを送ると、サーバーが返すのは「そのコメント 1 件」だけ。画面で一覧に足す方法もあるが、**サーバーの並び順・コメント数・他の人が同時に書いたコメントが、ずれる**。そこで、送れたら、一覧を読み直す（いいねは、返事に数が入っているので、読み直さなかった）。
- 注意：**送信は成功したが、読み直しだけ失敗**したとき、入力欄にエラーを出すと、利用者が送り直して、二重になる。別の場所に、「送れましたが、一覧を読み直せませんでした」と出す

### 同じ部品を使い回す
コメントの入力欄と、返信の入力欄は、ほぼ同じ。**違う所（名前・ボタンの文字・何をするか）だけを、外から渡す**（`label`・`submitLabel`・`onSubmit`）。280 文字の数え方（`MAX_POST_LENGTH`）も、投稿のモーダルと同じものを使う。

### 画面の権限は「見せるか」、本当の権限はサーバー
削除ボタンは、書いた人と投稿した人にだけ出す。でも、ボタンを隠すのは**親切**であって**守り**ではない（curl で直接送れる）。本当の判断は、サーバーの 403。画面とサーバーの二重で、役割が違う。

### 読み上げの名前
「削除」ボタンが並ぶので、名前に「どのコメントか」を入れる（例：「DemoBのコメント「First comment」を削除」）。本文の頭 20 文字を切り出す関数 `excerpt` は、投稿とコメントで共用するため、`timeline/format.ts` に移した。

## 3. つまずき
- **アイコン名**：`@mui/icons-material` の版 9 では `ChatBubbleOutlined`（`...Outline` はない）。`build` が教えてくれた。
- **lint の指摘**：読み込みの関数を、effect の中で呼ぶと「effect の中で、すぐに state を変えている」と指摘された。読み込みを effect の中の `Promise` の連なりにして、やり直しは「回数」を増やして effect を動かす形にした。ついでに、**画面を離れたあとに、前の読み込みの結果が入り込まない**よう、`cancelled` の印を付けた。
- **テスト**：無効なボタンは、`userEvent` では押せない（`pointer-events: none`）。「二重に送れない」は、フォームを直接送って確かめた。
