# フォロー中・フォロワーの一覧の API

2026-11-21。Issue #145。プロフィールとフォロー（機能定義書 07）の 3 つ目。講義では解説がなかったので、これまでの部品（フォロー、いいねの「押したか」のまとめ読み、投稿の一覧の「1 件多く読む」）を組み合わせて作った。

## 1. 作った API（2 つ）

| メソッド | パス | 返す人 |
|---|---|---|
| GET | `/api/users/{username}/followers` | その人を**フォローしている人**（フォロワー） |
| GET | `/api/users/{username}/following` | その人が**フォローしている人**（フォロー中） |

- どちらもログインなしで見られる（PF-5）。`SecurityConfig` の GET の許可に、2 本足した
- 応答は `{ users: [ { id, username, displayName, bio, followedByMe } ], hasNext }`。**メールは入れない**

## 2. follower と followee：向きに注意

`follows` 表の 1 行は「**follower が、followee を、フォローしている**」。

| 欲しい一覧 | 探す列 | 取ってくるユーザーの列 |
|---|---|---|
| フォロワー（私をフォローしている人） | `followee_id` ＝ 私 | `follower_id` の人 |
| フォロー中（私がフォローしている人） | `follower_id` ＝ 私 | `followee_id` の人 |

2 つの SQL は、**探す列と、JOIN でつなぐ列が、逆**になっているだけ（ノート 19 の JOIN の復習と同じ形。`JOIN users u ON u.id = f.follower_id`）。

## 3. 作りのポイント

- **取り出す列を、明示する**：`SELECT *` ではなく、`id`・`username`・`display_name`・`bio` だけ。メールやパスワードのハッシュは、そもそも取り出さない（出してはいけない物は、**取り出さない**のがいちばん安全）。
- **「自分がフォローしているか」は、まとめて 1 回**：一覧の人 N 人ぶんの id を `IN (…)` で渡して、1 回で聞く（いいねの「押したか」と同じ。N+1 を避ける）。全部で、ユーザー 1 ＋ 一覧 1 ＋ フォロー済み 1 ＝ **3 回**（ログインなしは 2 回）。2 人でも 6 人でも同じ回数になることを、テストで数えた。
- **並び**：`ORDER BY created_at DESC, id DESC`。「新しい順」で、同じ日時のときは id で順番を決める（毎回同じ順で返すため）。
- **最初の 50 件だけ**（ユーザー決定）：1 件多く（51 件）読み、50 件に切って、余りがあれば `hasNext = true`。続きの読み込みは、必要になったとき足す。

## 4. テスト（8 件）と、わざと壊す確認
- 新しい順／フォロー中の向き／`followedByMe`（ログインなし・自分自身は false）／404／`size` 0・51 で 400／`hasNext`／メール・ハッシュが出ない／SQL の回数
- **わざと壊して、赤くなるか確かめた**：並び順を昇順にすると、並び順のテスト 2 件だけが落ちた。ログインなしの許可を外すと、全 8 件が落ちた（401）。戻すと、緑。
- **気づき**：2 つを同時に壊すと、どちらの影響か分からなくなる（最初は全部が 401 で落ちて、並び順のテストが働いているか見えなかった）。**壊すのは、1 回に 1 か所**。
