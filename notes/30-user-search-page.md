# ユーザー検索の画面

2026-11-22。Issue #159。API（ノート 29）の続き。ヘッダーに検索欄を置き、検索結果の画面を作った。

## 1. 作った物
| 物 | 役目 |
|---|---|
| `Header.tsx` の検索欄 | 入力して Enter → `/search?q=…` へ移動。空・空白だけなら、何も起きない |
| `SearchPage.tsx`（`/search`） | URL の `q` を読んで、結果の一覧を出す |
| `useUserSearch` | 結果の読み込み（失敗・やり直し）と、行ごとのフォロー・解除 |

| `useFollowToggle` | 行ごとのフォロー・解除の処理（**フォロー一覧と共通**） |

## 2. 「検索の言葉」は、URL に持たせる
検索結果の画面は、`/search?q=山田` のように、**言葉を URL に入れる**。

- URL を貼れば、同じ結果が開く。更新（再読み込み）しても、戻るボタンを押しても、結果が消えない
- 画面の中だけ（`useState`）に持つと、更新で消える。URL に持つと、「いまの状態」が、URL という形で残る
- `useSearchParams` で `q` を読む。`encodeURIComponent` で、日本語や `&` などを安全に URL に入れる
- 言葉が変わったら、`key={q}` で結果の部品を作り直す（前の結果が、残らない）

## 3. 共通にした部品（既存のテストを、1 件も直さずに通した）
フォロー・フォロワーの一覧にあった「1 人分のカード」と「フォロー・解除の処理」を、取り出して、検索結果でも使った。

- 見た目や動きを変えずに、中身の置き場所だけを変える作業（**リファクタリング**）。**既存のテスト 29 件が、無修正で通った**ことが、「壊れていない」証拠になる
- 「フォロー・解除の処理」は、結果（サーバーが返した状態）を待ってから、その行のボタンを変える。連打は、「印」（`useRef`）で止める（いいね・プロフィールと同じ）

## 4. 検索欄を、狭い画面でも崩さない
- `Toolbar` に `flexWrap: 'wrap'`、検索欄に `order: { xs: 3, sm: 0 }` と `flexBasis: { xs: '100%', sm: 240 }`
- 広い画面では、タイトルの右に 240px。**狭い画面（スマホ）では、2 段目に回って、横いっぱい**になる（390px 幅のブラウザで確認）

## 5. 確かめたこと

- **わざと壊して、1 回に 1 か所**：空の確認を外す／`isMe` を外す／ログインへの案内を外す
- 本物のブラウザと本物のバックエンドで：「srch_a_b」で `a_b` の人だけが出る（`axb` の人は混ざらない）／「srch」で大文字の `DemoSrchMixed` も出る／日本語の表示名「山田」で探せる／結果からフォロー → ボタンが「フォローを解除する」に変わる／「フォロー中」の空の案内に、検索への誘導が出る／狭い画面で、ヘッダーが崩れない／コンソールのエラー・警告は 0 件

## 6. つまずき・気づき
- **最初のテストは、壊しを見逃した。** 「空のときに動かない」のテストが、「通信がない」「結果の見出しがない」しか確かめていなかった。確認を外しても、「入力してください」の画面に移るだけで、通信も見出しも出ないので、テストが通ってしまった。**「画面が動かない」ことを、直接確かめる**（移った先の案内の文が出ないこと）ように強くしたら、壊しを見つけた
  - テストは、「正しい実装で通る」だけでなく、**「間違った実装で落ちる」**ことで、役に立つ。ノート 27（フォロー中の API）と、同じ気づき
- ブラウザの確認で、日本語の表示名のユーザーを curl で登録するとき、Git Bash では、日本語が文字化け（400）になった。JSON を**ファイル**（UTF-8）に書いて、`--data-binary @ファイル` で送ると、登録できた
- ログインのボタンを押した直後にページを移動すると、ログインが終わる前に画面が読み直されて、ログインできていなかった。**画面の変化を待ってから、次の操作へ**
