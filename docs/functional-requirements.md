# 機能一覧

RaiseTimeLine の機能の概要（入口）。機能が多く、1 つ 1 つが重いため、**詳細は、機能ごとの機能定義書（[features/](features/)）に分けている**。

> **状態：ドラフト（2026-11-13）。** 「【未決】」は、まだ決まっていない点。「【補足】」は、Claude Code が補った提案（ユーザーの確認待ち）。

## 1. 最初に作る機能（一覧）

| # | 機能 | 概要 | 機能定義書 |
|---|---|---|---|
| 01 | 認証 | ユーザー登録（ログインとは別の画面）、ログイン、ログアウト | [01-auth.md](features/01-auth.md) |
| 02 | 投稿 | 280 文字までの投稿、**編集**、**削除**（自分の投稿だけ） | [02-post.md](features/02-post.md) |
| 03 | 画像 | 投稿の画像、アイコン画像（保存先は AWS S3） | [03-image.md](features/03-image.md) |
| 04 | タイムライン | **全体**と**フォロー中**の 2 種類 | [04-timeline.md](features/04-timeline.md) |
| 05 | コメント | 投稿へのコメント。**数が分かる**。**投稿した本人も、自分の投稿にできる** | [05-comment.md](features/05-comment.md) |
| 06 | いいね | 投稿へのいいね。**数が分かる**。**投稿した本人も、自分の投稿にできる** | [06-like.md](features/06-like.md) |
| 07 | プロフィール・フォロー | ユーザー名・アイコン・自己紹介、フォロー・フォロワー。ユーザー名からプロフィールへ移動して、フォロー | [07-profile-follow.md](features/07-profile-follow.md) |
| 08 | ユーザー検索 | ユーザー名で検索 | [08-user-search.md](features/08-user-search.md) |

- 操作の流れ（ユースケース UC-1〜12）は、各機能定義書にある。一覧は [ユースケース](use-cases.md)
- 機能どうしのつながり：認証（01）は、すべての土台。画像（03）は、投稿（02）とプロフィール（07）が使う。タイムライン（04）は、投稿（02）とフォロー（07）を使う

## 2. 将来追加する機能（候補。【補足】）
- 通知（いいね・コメント・フォローがあったとき）
- 投稿の本文の検索
- ハッシュタグ
- ブロック・ミュート
- パスワードの再設定
- スマホ対応

## 3. 対象外（作らないもの）
- **インプレッション数の表示**（差別化）
- **リツイート（再投稿）**（差別化）
- ダイレクトメッセージ（個別のやり取り）
- 動画の投稿
- 管理者の機能（【未決】要るか。[01 認証](features/01-auth.md) の AUTH-8）

## 4. 未決の点
機能ごとの未決は、各機能定義書の「7. 未決の点」にまとめてある。

| 機能 | 未決の件数 | 主な点 |
|---|---|---|
| [01 認証](features/01-auth.md) | 8 | 認証の方式、ログインに使う ID、ユーザー名・パスワードの条件、退会、管理者 |
| [02 投稿](features/02-post.md) | 4 | 「編集済み」の表示、削除した投稿のコメント・いいね・画像の扱い |
| [03 画像](features/03-image.md) | 5 | S3 の公開・非公開、枚数・サイズ・種類、アップロードの方式 |
| [04 タイムライン](features/04-timeline.md) | 4 | 「フォロー中」に自分の投稿を含めるか、件数が多いときの見せ方 |
| [05 コメント](features/05-comment.md) | 6 | 返信を作るか、コメント数に返信を含めるか、削除・編集 |
| [06 いいね](features/06-like.md) | 3 | コメントへのいいね、いいねした人の一覧 |
| [07 プロフィール・フォロー](features/07-profile-follow.md) | 5 | ユーザー名の変更、フォロー一覧の画面 |
| [08 ユーザー検索](features/08-user-search.md) | 3 | 一致のしかた、並び順、検索の欄の置き場所 |

機能をまたぐ未決：

|---|---|
| X-1 | ロードバランサーを使う範囲（費用）。インフラの構成図（EC2・RDS・ALB・S3）。NAT Gateway を使うか |
| X-2 | 最初に作る範囲（優先順位）と、進め方（機能ごとか、API 先行か） |
| X-3 | 通信の HTTPS（ドメイン・証明書）をどうするか（学習の範囲） |
