# 機能定義書 02：投稿（投稿・編集・削除）

> **状態：ドラフト（2026-11-13）。** 「【未決】」は、まだ決まっていない点。「【補足】」は、Claude Code が補った提案（ユーザーの確認待ち）。
> 全体の機能は [機能一覧](../functional-requirements.md) を参照。画像は [03 画像](03-image.md)。

## 1. 概要と目的
- 短い文章を投稿し、あとから直したり、消したりできる、このアプリの中心の機能
- 本文は、**280 文字まで**（講義の内容）

## 2. 決まっていること
- 本文は、280 文字まで。空の投稿はできない
- 編集・削除は、**自分の投稿だけ**（他の人の投稿は、サーバー側でも拒否する）
- 削除の前に、確認メッセージを表示する
- 投稿の表示：投稿者のユーザー名（アイコン画像つき）、本文、画像、投稿日時、いいねの数、コメントの数
- 入力中に、残りの文字数が分かる（【補足】）
- インプレッション数は、表示しない（作らない機能）。リツイートも、ない

## 3. 操作の流れ（ユースケース）

### UC-3: 投稿する（画像つきを含む）
- 事前条件：ログインしている
- 基本の流れ：
  1. 投稿の入力欄に、本文を入力する（残りの文字数が分かる）
  2. 必要なら、画像を選ぶ（[03 画像](03-image.md)）
  3. 「投稿」を押す
  4. 投稿が、タイムラインの一番上に表示される
- 例外の流れ：
  - 本文が空、または 281 文字以上のときは、投稿できない
  - 画像が、条件（種類、サイズ）を満たさないときは、投稿できず、理由を表示する

### UC-4: 自分の投稿を編集する
- 事前条件：自分の投稿である
- 基本の流れ：
  1. 自分の投稿の「編集」を押す
  2. 本文を直して、「保存」を押す（「キャンセル」で、直しを捨てる）
  3. 投稿の表示が、直した内容になる（【未決】「編集済み」の表示）
- 補足：他の人の投稿には、「編集」が表示されない。サーバー側でも、拒否する。画像の差し替え・削除ができるかは【未決】

### UC-5: 自分の投稿を削除する
- 事前条件：自分の投稿である
- 基本の流れ：
  1. 自分の投稿の「削除」を押す
  2. 確認メッセージが表示される
  3. 「削除する」を押す
  4. 投稿が、表示されなくなる（付いていたコメント・いいね・画像の扱いは【未決】）
- 例外の流れ：確認メッセージで「キャンセル」を押したら、削除されない

## 4. 画面に出るもの
- 投稿の入力欄（本文、残りの文字数、画像を選ぶボタン、「投稿」ボタン）
- 投稿のカード（ユーザー名・アイコン、本文、画像、日時、いいね数・コメント数、自分の投稿だけ「編集」「削除」）
- 編集の入力欄、削除の確認メッセージ
- 詳細は、画面設計（これから）で定める

## 5. 使うデータ
- POST（本文、画像の場所、投稿日時、編集日時）。[データ設計](../data-design.md) 2.2

## 6. エラー・例外
- 280 文字を超える、空、画像の条件違反：投稿・保存できず、理由を表示する
- 他の人の投稿を、編集・削除しようとした（画面を通さない直接の要求）：サーバーが拒否する
- すでに削除された投稿を編集しようとした：「投稿が見つかりません」と表示する（【補足】）

## 7. 未決の点
| ID | 未決の点 |
|---|---|
| POST-1 | 編集した投稿に「編集済み」と表示するか |
| POST-2 | 削除した投稿の、コメント・いいね・画像の扱い（一緒に消す、など）。本当に消すか、消したことにする（論理削除）か |
| POST-3 | 編集で、画像の差し替え・削除ができるか |
| POST-4 | 編集できる期間の制限（たとえば投稿から一定時間）はあるか（ふつうは、なし） |
