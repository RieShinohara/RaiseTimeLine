# 機能定義書 02：投稿（投稿・編集・削除）

> **状態：ドラフト（2026-11-13）。** 「【未決】」は、まだ決まっていない点。「【補足】」は、Claude Code が補った提案（ユーザーの確認待ち）。
> 全体の機能は [機能一覧](../features.md) を参照。画像は [03 画像](03-image.md)。

## 1. 概要と目的
- 短い文章を投稿し、あとから直したり、消したりできる、このアプリの中心の機能
- 本文は、**280 文字まで**（講義の内容）

## 2. 決まっていること
- 本文は、280 文字まで。空の投稿はできない
- 編集・削除は、**自分の投稿だけ**（他の人の投稿は、サーバー側でも拒否する）
- 削除の前に、確認メッセージを表示する
- 投稿の表示：投稿者のユーザー名（アイコン画像つき）、本文、画像、投稿日時、いいねの数、コメントの数
- 入力中に、残りの文字数が分かる（【補足】）
- インプレッション数は、表示しない（作らない機能）。リツイートも、ない
- **編集した投稿には、「編集済み」と表示する**（POST-1。2026-11-13 決定）
- **削除は、投稿と、付いていたコメント・いいね・S3 の画像を、すべて本当に消す**（POST-2。2026-11-13 決定。あとから元に戻せない）
- **編集できるのは、本文だけ**。画像の差し替え・削除はできない（画像を変えたいときは、投稿を削除して、新しく投稿する）（POST-3。2026-11-13 決定）
- **編集できる期間に、制限はない**（POST-4。2026-11-13 決定）
- **新しい投稿は、タイムラインの上の入力欄ではなく、「＋投稿」ボタンから開く、モーダル（画面の上に重なる入力画面）で行う**（POST-5。2026-11-16 ユーザーが決定。講義 28 の先生の作りにそろえた）。モーダルの中身は、本文、残りの文字数、画像を選ぶボタン、「投稿」ボタン、閉じる操作。コメントの入力欄と、投稿の編集は、今までどおり（モーダルにしない）

## 3. 操作の流れ（ユースケース）

### UC-3: 投稿する（画像つきを含む）
- 事前条件：ログインしている
- 基本の流れ：
  1. 「＋投稿」ボタンを押して、投稿のモーダルを開く（POST-5）
  2. 本文を入力する（残りの文字数が分かる）
  3. 必要なら、画像を選ぶ（[03 画像](03-image.md)）
  4. 「投稿」を押す。モーダルが閉じる
  5. 投稿が、「全体」のタイムラインの一番上に表示される（「フォロー中」を見ているときは、自分の投稿は出ないので、「投稿しました。『全体』と、自分のプロフィールで見られます」とお知らせを出す。TL-1）
- 例外の流れ：
  - 本文が空、または 281 文字以上のときは、投稿できない
  - 投稿に失敗したときは、モーダルを閉じず、理由を表示する（入力した内容を、失わない）【補足】
  - 入力のあとに、モーダルを閉じようとしたときの確認は、しない【補足】（学習の範囲では、簡単にする）
  - 画像が、条件（種類、サイズ）を満たさないときは、投稿できず、理由を表示する

### UC-4: 自分の投稿を編集する
- 事前条件：自分の投稿である
- 基本の流れ：
  1. 自分の投稿の「編集」を押す
  2. 本文を直して、「保存」を押す（「キャンセル」で、直しを捨てる）
  3. 投稿の表示が、直した内容になり、「編集済み」と表示される
- 補足：他の人の投稿には、「編集」が表示されない。サーバー側でも、拒否する。編集できるのは本文だけで、画像は変えられない。いつでも編集できる
- 本文を、変えずに「保存」したときは、「編集済み」にしない（【補足】本文が同じなら、更新しない）

### UC-5: 自分の投稿を削除する
- 事前条件：自分の投稿である
- 基本の流れ：
  1. 自分の投稿の「削除」を押す
  2. 確認メッセージが表示される
  3. 「削除する」を押す
  4. 投稿と、付いていたコメント・いいね・画像が、すべて消える（元に戻せない。確認メッセージに、そのことを書く）
- 例外の流れ：確認メッセージで「キャンセル」を押したら、削除されない

## 4. 画面に出るもの
- 「＋投稿」ボタン（ログインしているときだけ）と、そこから開く投稿のモーダル（本文、残りの文字数、画像を選ぶボタン、「投稿」ボタン、閉じる操作）
- 投稿のカード（ユーザー名・アイコン、本文、画像、日時、いいね数・コメント数、自分の投稿だけ「編集」「削除」）
- 編集の入力欄、削除の確認メッセージ
- 詳細は、実装した画面（[04 タイムライン](04-timeline.md) 4）が正（投稿・編集・削除の画面は、実装済み。画像を選ぶボタンは、画像の機能のときに足す）

## 5. 使うデータと API
- POST（本文、画像の場所、投稿日時、編集日時）。[データ設計](../database-design.md) 2.2
- **API**（講義 28 の API 設計にそろえた。2026-11-16）。タイムラインの取得・新着件数は [04](04-timeline.md) 5：

| Method | Path | 説明 |
|---|---|---|
| POST | `/api/posts` | 投稿の作成 → **201**。ログイン必須。本文は 1〜280 文字（空・空白だけは 400）。**本文の前後の空白（全角の空白・改行を含む）は、サーバーが取ってから、検査・保存する**（品質チェック B9。途中の空白・改行は、そのまま）。投稿した人は、ログイン中の人 |
| PUT | `/api/posts/{id}` | 投稿の編集（**本文だけ**）。**本人だけ**。本文が同じなら、更新せず、「編集済み」にしない |
| DELETE | `/api/posts/{id}` | 投稿の削除 → **204**。**本人だけ** |

- **編集・削除の画面**（講義 28。2026-11-16 ユーザーが決定）：
  - 投稿カードの右下に、**鉛筆（編集）とゴミ箱（削除）のアイコン**。**自分の投稿だけ**に出す（本当の確認は、サーバー）
  - **編集は、モーダル**（投稿と同じ部品を使う。タイトル「投稿を編集」、今の本文が入っている、「保存」「キャンセル」）。本文が元と同じときは、「保存」を押せない。保存すると、同じ場所で置き換わり、「編集済み」と出る。失敗したら、閉じず、入力を残して理由を出す
  - **削除は、確認のダイアログ**：タイトル「投稿を削除」（右上に閉じる ×。「閉じる」は、見出しの外に置く。2026-11-19、品質チェック F11）、「この投稿を削除しますか？」、「削除した投稿は元に戻せません。」、「キャンセル」と、赤い「削除する」。消すと、一覧から外れる。失敗したら、閉じず、理由を出す
- 編集・削除のエラー：ログインなしは **401**、他の人の投稿は **403**（「他の人の投稿は、編集・削除できません」）、存在しない（削除済みを含む）は **404**（「投稿が見つかりません」）
- 本文の 280 文字は、サーバー側は Java の文字数（UTF-16）で数える。絵文字など、1 文字が 2 つ分に数えられる文字は、実際より多く数える（学習の範囲では、そのまま。[ノート 02](../../notes/02-future-feature-ideas.md)）

## 6. エラー・例外
- 280 文字を超える、空、画像の条件違反：投稿・保存できず、理由を表示する
- 他の人の投稿を、編集・削除しようとした（画面を通さない直接の要求）：サーバーが拒否する
- すでに削除された投稿を編集しようとした：「投稿が見つかりません」と表示する（【補足】）
