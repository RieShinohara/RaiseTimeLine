# 機能定義書 07：プロフィール・フォロー

> **状態：ドラフト（2026-11-13）。2026-11-20 に、【補足】はすべて「決定」とした（ユーザーが承認）。** フォローの API とプロフィールの API（8）は実装済み（Issue #139・#141）。フォロー中・フォロワーの一覧の API も実装済み（Issue #145）。**プロフィールの画面（表示・フォロー／解除・投稿の一覧）は実装済み**（Issue #147。9）。**プロフィールの編集の画面も実装済み**（Issue #149。9）。フォロー一覧の画面は、これから。
> **アイコン画像は、あとに回す**（2026-11-20 ユーザーが決定。AWS（S3）に触るのは、デプロイに近づいてから）。プロフィールの編集は、まず、**表示名と自己紹介だけ**。画面のアイコンは、仮の丸いマーク（名前の頭文字）にして、画像ができたら差し替える。
> 全体の機能は [機能一覧](../features.md) を参照。画像は [03 画像](03-image.md)。

## 1. 概要と目的
- ユーザーを紹介する場所（プロフィール）と、気になるユーザーの投稿を追う仕組み（フォロー）
- 投稿やコメントのユーザー名から、プロフィールへ移動し、そこからフォローできる

## 2. 決まっていること
- プロフィールに、ユーザー名、アイコン画像、自己紹介、フォロー数、フォロワー数、そのユーザーの投稿の一覧を表示する
- プロフィールには、**表示名**と、**@ユーザー名**も表示する（2026-11-14。[01 認証](01-auth.md)）
- 自分のプロフィールは、編集できる（**表示名**、アイコン画像、自己紹介）。表示名は、50 文字まで。変えられる（2026-11-14 決定）
- フォロー・フォロー解除は、他のユーザーのプロフィールから行う
- 自分自身は、フォローできない（【補足】）
- 投稿・コメントのユーザー名を押すと、そのユーザーのプロフィールへ移動する
- フォローしているユーザーの投稿は、「フォロー中」のタイムラインに出る（[04](04-timeline.md)）
- **ユーザー名は、あとから変えられない**（登録したときのまま）（PF-1。2026-11-13 決定）
- **フォロー中・フォロワーの一覧の画面を作る**。数を押すと、一覧が開き、そこからプロフィールへ移動して、フォローできる（PF-3。2026-11-13 決定）
- 【補足】自己紹介は、160 文字まで（PF-2）
- 【補足】プロフィールの投稿の一覧は、タイムラインと同じ見せ方（新しい順、下へ進むと自動で増える。1 回 20 件）（PF-4）

## 3. 操作の流れ（ユースケース）

### UC-9: プロフィールを見る
- 事前条件：なし（ログインなしでも見られる。PF-5）
- 基本の流れ：
  1. 投稿やコメントのユーザー名を押す（またはユーザー検索の結果から選ぶ）
  2. そのユーザーのプロフィールが表示される（ユーザー名、アイコン画像、自己紹介、フォロー数、フォロワー数、投稿の一覧）
- 例外の流れ：存在しないユーザーのときは、「ユーザーが見つかりません」と表示する（【補足】）

### UC-10: ユーザーをフォローする・解除する
- 事前条件：ログインしている。他のユーザーのプロフィールを開いている
- 基本の流れ：
  1. 「フォロー」を押す
  2. ボタンが「フォロー解除」に変わり、相手のフォロワー数が 1 増える
  3. 「フォロー解除」を押すと、元に戻る
- 補足：自分のプロフィールには、「フォロー」を表示しない

### UC-16: フォロー中・フォロワーの一覧を見る
- 事前条件：なし（ログインなしでも見られる。ただし、一覧からのフォロー・解除は、ログインが必要）。プロフィールを開いている
- 基本の流れ：
  1. プロフィールの「フォロー中」または「フォロワー」の数を押す
  2. その一覧が表示される（ユーザー名、アイコン。【補足】新しい順）
  3. ユーザーを選ぶと、そのプロフィールが開く（UC-9）。一覧のボタンから、そのままフォロー・解除もできる（UC-10）
- 例外の流れ：0 件のときは、「まだいません」と表示する（【補足】）

### UC-11: 自分のプロフィールを編集する
- 事前条件：ログインしている。自分のプロフィールを開いている
- 基本の流れ：
  1. 自分のプロフィールの「編集」を押す
  2. 表示名、アイコン画像、自己紹介を変更して、「保存」を押す（ユーザー名は、変えられない）
- 例外の流れ：自己紹介が文字数の上限を超えるとき、画像が条件に合わないときは、保存できず、理由を表示する

## 4. 画面に出るもの
- プロフィールの画面（ユーザー名、アイコン、自己紹介、フォロー数・フォロワー数、フォロー／フォロー解除ボタン、投稿の一覧）
- プロフィールの編集の画面（または窓）
- フォロー中・フォロワーの一覧（各ユーザーの、ユーザー名・アイコン・フォロー／解除ボタン。【補足】）
- 詳細は、画面設計（これから）で定める

## 5. 使うデータ
- USER（ユーザー名、アイコン、自己紹介）、FOLLOW（フォローする側・される側）、POST。[データ設計](../database-design.md) 2.1、2.5

## 6. エラー・例外
- 自分自身をフォローしようとした（画面を通さない直接の要求）：サーバーが拒否する
- すでにフォローしている相手を、もう一度フォローした：二重に作らない（エラーにせず、そのまま）（【補足】）
- 他の人のプロフィールを、編集しようとした：サーバーが拒否する

## 8. API（実装。2026-11-20〜21。フォロー：Issue #139、プロフィール：Issue #141、一覧：Issue #145）
| メソッド | パス | 内容 |
|---|---|---|
| GET | `/api/users/{username}` | プロフィールの取得。**ログイン不要**（PF-5）。`id`・`username`・`displayName`・`bio`（未設定は null）・`followingCount`・`followerCount`・`followedByMe`（ログインなしは false）。**メールアドレスは含めない**。存在しないユーザーは 404 |
| PUT | `/api/users/{username}` | 自分のプロフィールの編集。入力は `displayName`（必須、前後の空白を取る、50 文字まで）と `bio`（160 文字まで。空・空白だけは null＝未設定）。**本人だけ**（他の人は 403、ログインなしは 401）。ユーザー名は変えられない（入力にあっても無視）。結果は、取得と同じ形 |
| GET | `/api/users/{username}/posts` | そのユーザーの投稿の一覧。**ログイン不要**。`before`・`size`（1〜50、省略は 20）・応答（`posts`・`hasNext`）は、タイムラインと同じ。いいね数・押したか・コメント数も付く。存在しないユーザーは 404 |
| GET | `/api/users/{username}/followers` | その人を**フォローしている人**の一覧（UC-16）。**ログイン不要**（PF-5）。`size`（1〜50、省略は 50）。範囲外は 400。応答は `users`（`id`・`username`・`displayName`・`bio`・`followedByMe`）と `hasNext`。**フォローした日時の新しい順**。`followedByMe`＝ログイン中の自分が、その人をフォローしているか（ログインなし・自分自身の行は false）。**メールアドレスは含めない**。存在しないユーザーは 404。続きの読み込み（ページ分け）は、必要になったとき足す【最初の 50 件だけ。2026-11-21 ユーザー決定】 |
| GET | `/api/users/{username}/following` | その人が**フォローしている人**の一覧。上と同じ形・同じ決まり |
| PUT | `/api/users/{username}/follow` | フォローする。**ログインが必要**（401）。結果は `followerCount`（相手のフォロワー数）と `following`（true）。すでにフォローしていても、エラーにしない（結果は同じ）。**自分自身は 400**（「自分自身は、フォローできません」）。存在しないユーザーは 404 |
| DELETE | `/api/users/{username}/follow` | 解除する。ログインが必要（401）。フォローしていなくても、エラーにしない。結果は `following`（false）。存在しないユーザーは 404 |

- ユーザー名は、大文字小文字を区別しない（登録のときの重複の確認と同じ決まり）
- 自分自身のフォローは、**DB の CHECK 制約でも止める**（アプリの確認をすり抜けても、行は作れない）
- 確認と追加の間に、相手が消えた場合は、外部キーが止めて、404 にする（投稿・いいねと同じ）
- 編集の道筋を `/api/users/me` にしなかったのは、`me` も、ユーザー名として登録できて、ぶつかるため（2026-11-20）
- `bio`・`icon_key` の列は、`users` 表に、最初（V1）からある。アイコン画像（`icon_key`）は、画像の機能（03）で扱う
- 一覧の SQL は、人数によらず、ログイン中は 3 回（ユーザー・一覧・フォロー済みか）、ログインなしは 2 回（テストで数えている）
- **未実装**：一覧の続きの読み込み、アイコン画像、フォロー一覧の画面（9 の「これから」）、「フォロー中」のタイムライン（[04](04-timeline.md)）

## 9. プロフィールの画面（実装。2026-11-21。Issue #147）
- URL：`/users/:username`。**ログインなしで見られる**（PF-5）。存在しないユーザーは、「ユーザーが見つかりません」
- 表示：頭文字のアイコン（アイコン画像は、画像の保存先〔S3〕を作るときに、投稿の画像と一緒に作る。`users.icon_key` は V1 からある）、表示名、@ユーザー名、自己紹介（未設定なら出さない）、フォロー中・フォロワーの数（数の表示だけ）、そのユーザーの投稿の一覧（新しい順、下へ進むと自動で増える。20 件ずつ。いいね・コメントを見る操作ができる）
- **フォロー／フォロー解除のボタン**：他の人のプロフィールだけ（自分には出さない。UC-10）。ログインなしで押すと、ログイン画面へ。結果（サーバーが返した数と状態）を待ってから変え、送信中は押せない（二重に送らない）。失敗したら、見た目と数は元のままで、理由を出す
- 入口：投稿カード・コメントの「表示名 @ユーザー名」を押す／ヘッダーの自分の名前を押す
- 【補足。2026-11-21】プロフィールの投稿の一覧には、編集・削除を出さない（タイムラインでできる。必要なら、あとで足す）
- **プロフィールの編集（UC-11。2026-11-21。Issue #149）**：自分のプロフィールに、フォローの代わりに「編集」ボタン → ダイアログ。**直せるのは、表示名（必須・50 文字まで）と自己紹介（160 文字まで・空なら未設定）だけ**（ユーザー名・メールは変えられない。アイコンは S3 のとき）。文字数は「n / 50」「n / 160」で見せる。**変更がないとき（前後の空白を取った内容が同じ）は、保存できない**。保存に成功すると、プロフィールの表示と、**ヘッダーの自分の名前もすぐ変わる**（ログイン情報として保存してある表示名も更新する）。失敗したときは、閉じずに理由を出し、入力も残す。開くたびに作り直す（前の入力が残らない）
- **これから**：フォロー中・フォロワーの一覧の画面（UC-16。プロフィールの数を押して開く）
