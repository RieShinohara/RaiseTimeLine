# 機能定義書 06：いいね

> **状態：ドラフト（2026-11-13）。実装の反映は 2026-11-19 まで（いいねした人の一覧は、これから）。** 「【未決】」は、まだ決まっていない点。「【補足】」は、Claude Code が補った提案（ユーザーの確認待ち）。
> 全体の機能は [機能一覧](../features.md) を参照。

## 1. 概要と目的
- 投稿に「いいね」と、軽く反応する機能
- **いいねの数が分かる**（講義の内容）
- **投稿した本人も、自分の投稿に、いいねできる**（ユーザー決定、2026-11-12）

## 2. 決まっていること
- ログインしているユーザーは、どの投稿にも、いいねできる（自分の投稿にも）
- 投稿ごとに、いいねの数を表示する
- 【補足】同じ投稿に、同じユーザーは、1 回だけ。もう一度押すと、取り消せる
- 【補足】自分が、いいねした投稿は、押した状態の見た目で分かる
- **いいねは、投稿に対してだけ**。コメントには、いいねできない（LIKE-1。2026-11-13 決定）
- **「誰がいいねしたか」の一覧を、見られる**。いいねの数を押すと、いいねした人の一覧が開き、そこから、プロフィールへ移動できる（LIKE-2。2026-11-13 決定）

## 3. 操作の流れ（ユースケース）

### UC-8: 投稿にいいねする・取り消す
- 事前条件：ログインしている（自分の投稿にも、できる）
- 基本の流れ：
  1. 投稿の「いいね」を押す
  2. いいねの数が 1 増え、押した状態の表示になる
  3. もう一度押すと、取り消され、数が 1 減る
- 例外の流れ：
  - 通信に失敗したときは、数と見た目を元に戻し、「うまくいきませんでした」と表示する（【補足】）
  - 同時に、同じ人が連続で押しても、1 回分しか数えない（二重のいいねを作らない）

### UC-15: いいねした人の一覧を見る
- 事前条件：なし（ログインなしでも見られる。AUTH-6）
- 基本の流れ：
  1. 投稿の「いいねの数」を押す
  2. いいねした人の一覧が表示される（ユーザー名、アイコン。新しい順。【補足】）
  3. ユーザーを選ぶと、プロフィールが開く（UC-9）
- 例外の流れ：いいねが 0 件のときは、数を押しても何も開かない、または「まだいいねがありません」と表示する（【補足】）
- 補足：自分の投稿でも、他の人の投稿でも、同じように見られる

## 5. 使うデータ
- POST_LIKE（投稿、ユーザー。同じ組み合わせは 1 つだけ）。いいね数は、POST_LIKE の件数。[データ設計](../database-design.md) 2.4

## 6. エラー・例外

- ログインしていない：ログインの画面へ案内する

## 8. API（実装。2026-11-18。Issue #111）
**Claude Code が補った点**（ユーザーが、2026-11-18 に確認済み）：一覧の応答に、各投稿の `likedByMe`（自分が押したか）を入れる（LIKE-4）。ハートの色を、一覧を見た時点で決められる（別の通信が要らない）。

| Method | Path | 説明 |
|---|---|---|
| PUT | `/api/posts/{id}/like` | いいねを押す。**ログインが必要**（401）。自分の投稿にも、できる。すでに押していても、エラーにしない（結果は同じ）。存在しない投稿は 404 |
| DELETE | `/api/posts/{id}/like` | いいねを取り消す。ログインが必要（401）。押していなくても、エラーにしない。存在しない投稿は 404 |
| GET | `/api/posts` | 各投稿に `likeCount`・`likedByMe` が付く（[04](04-timeline.md) 5） |

- 応答（押す・取り消す）：`{ likeCount, liked }`。画面は、この結果を待ってから、数と見た目を変える（LIKE-3）
- **二重のいいねを作らない**：表の主キーが `(post_id, user_id)` の組み合わせ。`INSERT ... ON CONFLICT DO NOTHING` で、確認と追加を 1 つの SQL で行うので、同時に 2 回押されても、1 行だけになる
- **N+1 を避ける**：一覧の SQL は、投稿 1 回 ＋ 数をまとめて 1 回（`GROUP BY`）＋ 押したかをまとめて 1 回（`IN`）。**件数によらず、3 回**（ログインなしは 2 回）。素直に 1 件ずつ聞くと、20 件で 41 回。テストで、回数を数えて確かめている
- **未実装**：いいねした人の一覧（UC-15。LIKE-2）。あとの Issue で作る
- 実装の確認：テスト（`PostLikeApiTests`、`PostSqlCountTests`）、`gradlew check` が成功

## 9. 画面（実装。2026-11-18。Issue #117）
- **ハートのボタン**を、投稿のカードの左下に出す。右に、いいねの数。押した状態は、**ハートの形（塗りつぶし）と色（赤）**で示し、`aria-pressed` でも伝える（色だけに頼らない）。ボタンの名前は、どの投稿かが分かるように、投稿者と本文の頭を入れる（例：「サンプルの投稿「こんにちは…」にいいねする」「…のいいねを取り消す」）
- **LIKE-3 のとおり、結果を待ってから変える**：押すと、サーバーに送り、返事（`likeCount`・`liked`）で、数と見た目を変える。**返事が来るまで、そのボタンは押せない**（連打しても 1 回だけ）。失敗したら、数と見た目は元のまま、「うまくいきませんでした（理由）」を、画面の下に数秒出す
- **ログインなしで押したら、ログインの画面へ移動**する（いいねの通信は、しない）。数は、ログインなしでも見える
- **一覧を読むときに、札を付ける**。札がないと、サーバーは「ログインなし」と判断して、`likedByMe` が常に false になる。期限切れの札は、先に更新してから読む（新着の件数と同じ落とし穴）
- トップ画面を開いたまま、ログインが切れたとき（札の更新も無効）は、前の人の「押した状態」は出さない（数は、そのまま）
- 自分の投稿にも、いいねできる（制限なし）
