# 機能定義書 04：タイムライン（全体・フォロー中）

> **状態：ドラフト（2026-11-13）。** 「【未決】」は、まだ決まっていない点。「【補足】」は、Claude Code が補った提案（ユーザーの確認待ち）。
> 全体の機能は [機能一覧](../features.md) を参照。

## 1. 概要と目的
- 投稿を、新しい順に並べて見る、メインの画面
- 2 種類ある：**全体**（全ユーザーの投稿）と、**フォロー中**（フォローしているユーザーの投稿）

## 2. 決まっていること
- 「全体」：全ユーザーの投稿を、新しい順に表示する
- 「フォロー中」：フォローしているユーザーの投稿を、新しい順に表示する
- 2 つを、切り替えて見られる
- 各投稿に、投稿者のユーザー名（アイコンつき）、本文、画像、投稿日時、いいね数、コメント数を表示する
- 投稿者のユーザー名を押すと、そのユーザーのプロフィールへ移動する（[07](07-profile-follow.md)）
- 誰もフォローしていないとき（または、フォローした人の投稿が、まだないとき）の「フォロー中」には、案内を表示する（【補足】「フォローしている人の投稿は、まだありません。気になる人を、ユーザー検索で探して、フォローしてみましょう」）
- **「フォロー中」は、フォローしている人の投稿だけ。自分の投稿は、入れない**（TL-1。2026-11-13 に「含める」と決め、2026-11-15 に変更。自分の投稿は、「全体」と自分のプロフィールで見られるため）
- **「フォロー中」を見ているときに投稿したら、「投稿しました。『全体』と、自分のプロフィールで見られます」とお知らせを出す**（2026-11-15 決定。投稿したのに、その画面に出ないと、不安になるため）
- **投稿が多いときは、下へ進むと、自動で続きを読み込む**（TL-2。2026-11-13 決定）。1 回に読み込む件数は、20 件（【補足】仮の値。実装・動作確認で調整する）
- **新しい投稿は、30 秒ごとに、自動で確かめる**（ポーリング。画面側の `setInterval`）。新しい投稿があったら、画面の上に浮かぶバナー（ボタン）「N 件の新しい投稿があります」（↑の矢印つき）を出す。**バナーは、スクロールや他の操作を止めない**（モーダルではない）。押すと、**一番上まで自動でスクロールして、最新の投稿を表示する**（TL-4。2026-11-16 ユーザーが決定。講義 28 にそろえた。最初の案「自動更新しない」から変更）
  - 【補足】自分が投稿したときは、バナーを出さず、一番上にすぐ出す
  - 【補足】別のタブを開いているなど、画面を見ていない間は、確認を止める。戻ってきたら、すぐに 1 回確かめて、30 秒ごとに戻る
  - 【補足】見ているタイムライン（「全体」か「フォロー中」）だけを確かめる
  - 【補足】バナーが出ているあいだに、さらに新しい投稿があったら、件数を増やす。確認の通信が失敗したときは、バナーも、エラーも出さず、次の確認を待つ
  - **実装（⑤-3b。2026-11-16）**：
    - 基準（`since`）は、**1 ページ目を読んだときの、一番上の投稿の `createdAt`**（サーバーが返した文字列のまま）。続き（2 ページ目以降）を読んでも、自分が投稿しても、変えない（変えると、古い投稿まで新着に数える・その間の他の人の新着を取りこぼす）。投稿が 1 件もないときは、`1970-01-01T00:00:00Z`（すべて新着）
    - バナーを押すと、1 ページ目から読み直して、一覧を入れ替え、基準を新しい一番上にして、一番上へスクロールする。読み直しに失敗したときは、バナーを残し、スクロールもしない（もう一度、押せる）
    - **期限切れのアクセストークンのまま確かめると、自分の投稿も新着に数えられる**（この API は、ログインなしでも使えるため、期限切れの札を「札なし」として扱う）。そこで、確かめる前に、札の期限（JWT の `exp`）を見て、切れていれば、先に更新する

## 3. 操作の流れ（ユースケース）

### UC-6: タイムラインを見る
- 事前条件：なし（「全体」は、ログインなしで見られる。「フォロー中」は、ログインが必要。TL-3）。「＋投稿」ボタンは、ログインしているときだけ出る
- 基本の流れ：
  1. ログイン後の画面で、「全体」と「フォロー中」を、切り替えて選ぶ
  2. 選んだタイムラインの投稿が、新しい順に表示される
  3. 各投稿に、ユーザー名、本文、画像、投稿日時、いいねの数、コメントの数が表示される
  4. 「＋投稿」ボタンから開くモーダルで、新しい投稿ができる（[02](02-post.md)。POST-5）
  5. 見ている間に、他の人の新しい投稿があると、30 秒以内に、「N 件の新しい投稿があります」のバナーが浮かぶ。押すと、一番上へスクロールして、最新の投稿が見える（TL-4）
- 例外の流れ：
  - 投稿が 1 件もないときは、「まだ投稿がありません」と表示する（【補足】）
  - 読み込みに失敗したときは、「読み込めませんでした」と表示する（【補足】）

## 4. 画面に出るもの
- 「全体」「フォロー中」の切り替え
- 「＋ 投稿する」ボタン（**画面の右下に固定の、浮かぶボタン**。下へ読み進めても、いつでも押せる。画面が広いときは、一覧の右端の内側。ログイン中だけ。2026-11-17 に、タブの行の右端から変更。Issue #85。講義 28 の画面は、参考にしただけで、先生の指示ではなかった）、投稿のカードの並び
- 投稿のカード（⑤-2）：アイコン（アイコン画像ができるまでは、**表示名の頭文字の丸**）、表示名、@ユーザー名、右上に日時（「2026/11/16 14:30」の形。見る人の時刻）、本文（改行はそのまま）、編集済みなら「編集済み」。右下に、自分の投稿だけ、編集・削除のアイコン（⑤-3a。[02](02-post.md) 5）。いいね数・コメント数は⑥で足す
- 「全体」のタブだけを置く（「フォロー中」のタブは、フォロー（⑦）のときに足す）。画面の上の帯（ヘッダー）の、検索・プロフィールのアイコンも、その機能のときに足す
- 一番下まで進んだときの、続きの読み込み中の表示、「これ以上ありません」の表示（【補足】）
- 新しい投稿を知らせる、浮かぶバナー（「↑ N 件の新しい投稿があります」）。「更新」の操作は、作らない（バナーが、その役目をする）
- 詳細は、画面設計（これから）で定める

## 5. 使うデータと API
- POST（新しい順は created_at）、FOLLOW（フォロー中の絞り込み）、集計としての POST_LIKE・COMMENT の件数。[データ設計](../database-design.md)
- **API**（講義 28 の API 設計にそろえた。2026-11-16 ユーザーが決定。投稿の作成・編集・削除は [02](02-post.md)）：

| Method | Path | 説明 |
|---|---|---|
| GET | `/api/posts?before={投稿id}&size=20` | タイムライン取得（新しい順）。**ログインなしで可**（TL-3）。`before` は、**この投稿 id より古いものを返す**（省略すると、最新から）。`size` は 1〜50（既定 20）。範囲外・`before` が数字でないときは 400 |
| GET | `/api/posts/new-count?after={投稿id}` | `after` **より新しい（id が大きい）**投稿の件数。ログイン中は、**自分の投稿を数えない**。ログインなしで可。`after` がない・負の数・数字でないと 400。投稿が 1 件もないときの基準は 0 |

- 応答（取得）：`{ posts: [...], hasNext }`。`hasNext` は、このあとに（もっと古い）続きがあるか（無限スクロールで、読み込みを続けるかの判断）。各投稿は、`id`・`body`・`createdAt`・`updatedAt`（編集していなければ空）・`author`（`id`・`username`・`displayName`。**メールアドレスは含めない**）
- 続きの指定は、**「ここより古いもの」方式（カーソル方式）**（2026-11-18 に、ページ番号方式から変更。Issue #87。先生の設計は参考で、そろえなくてよいとユーザーが了承）。ページ番号方式は、スクロール中に新しい投稿が入ると重複し、削除されると取りこぼした。投稿 id（増える一方の番号）を目印にすると、どちらも起きない。並び順も、id の大きい順（＝新しい順）
- **新着の基準は、1 ページ目の一番上の投稿の `id`**。日時を使わないので、DB（マイクロ秒）と JavaScript（ミリ秒）の細かさの違いによるずれは、起きない
- 【画面側の変更は別の Issue（フロントエンド）。それまで、画面は旧方式のまま動かない】
- ⑤の段階では、いいね数・コメント数・画像は、応答に含めない（いいね・コメントは⑥、画像は画像の機能のとき）

## 6. エラー・例外
- 上の UC-6 の例外のとおり
- 新しい投稿の確認（ポーリング）に失敗したときは、何も出さず、次の確認（30 秒後）を待つ（【補足】）
