# 機能定義書 01：認証（ユーザー登録・ログイン・ログアウト）

> **状態：ドラフト（2026-11-13）。** 「【未決】」は、まだ決まっていない点。「【補足】」は、Claude Code が補った提案（ユーザーの確認待ち）。
> 全体の機能は [機能一覧](../features.md) を参照。

## 1. 概要と目的
- 利用者が、自分のアカウントを作り（登録）、自分として使い始め（ログイン）、使い終える（ログアウト）ための機能
- 「誰が投稿したか」「誰がいいねしたか」「誰が自分の投稿を直せるか」を決める、**すべての機能の土台**
- 登録は、**ログインとは別の画面**で行う（講義の内容）

## 2. 決まっていること
- ユーザー登録とログインは、別の画面
- 入力：ユーザー名、パスワード
- ユーザー名は、重複できない（【補足】ユーザー検索・表示に使うため）
- パスワードは、そのままの形では保存しない（ハッシュ化。[非機能要件](../non-functional-requirements.md) 4）
- 認証が必要な操作（投稿・コメント・いいね・フォロー・編集・削除）は、ログインしていないと、できない（サーバー側で拒否する）
- ログインの失敗の文言は、「ユーザー名かパスワードが違います」とし、どちらが違うかは教えない（【補足】）

## 3. 操作の流れ（ユースケース）

### UC-1: ユーザー登録する
- 利用者：新しい利用者
- 目的：アカウントを作る
- 事前条件：ログインしていない
- 基本の流れ：
  1. 「ユーザー登録」の画面を開く
  2. ユーザー名とパスワードを入力する（【未決】メールアドレス）
  3. 「登録」を押す
  4. アカウントが作られる（登録後に、ログインした状態にするか、ログイン画面へ進むかは【未決】）
- 例外の流れ：
  - ユーザー名が、すでに使われているときは、登録できず、理由を表示する
  - 入力が条件を満たさないとき（空、文字数、パスワードの強さ）は、登録できず、理由を表示する

### UC-2: ログイン・ログアウトする
- 目的：自分のアカウントで使い始める／終える
- 基本の流れ：
  1. 「ログイン」の画面で、ユーザー名とパスワードを入力して、「ログイン」を押す
  2. 成功したら、タイムラインの画面へ進む
  3. 使い終わったら、「ログアウト」を押す。ログインの画面へ戻る
- 例外の流れ：
  - ユーザー名かパスワードが違うときは、ログインできず、「ユーザー名かパスワードが違います」と表示する
  - ログインしていない状態で、ログインが必要な画面を開いたときは、ログインの画面へ案内する（【補足】）

## 4. 画面に出るもの
- ユーザー登録の画面：ユーザー名、パスワードの入力欄、「登録」ボタン、ログイン画面へのリンク
- ログインの画面：ユーザー名、パスワードの入力欄、「ログイン」ボタン、登録画面へのリンク
- ログイン後の画面の見出し：「ログアウト」ボタン、自分のプロフィールへの入口
- 詳細は、画面設計（これから）で定める

## 5. 使うデータ
- USER（ユーザー名、パスワードのハッシュ）。[データ設計](../database-design.md) 2.1

## 6. エラー・例外
- 上の UC-1、UC-2 の例外の流れのとおり
- 【補足】ログインの失敗を繰り返す攻撃への対策：下の未決のとおり

## 7. 未決の点
| ID | 未決の点 |
|---|---|
| AUTH-1 | 認証の方式（セッション方式か、トークン方式か。講義に合わせて決める） |
| AUTH-2 | ログインに使う ID は何か（ユーザー名か、メールアドレスか）。メールアドレスの項目を持つか |
| AUTH-3 | 登録後に、そのままログインした状態にするか |
| AUTH-4 | ユーザー名の文字数・使える文字。パスワードの条件（長さなど） |
| AUTH-5 | ログイン失敗を繰り返す攻撃への対策（回数の制限）を、学習の範囲でやるか |
| AUTH-6 | ログインしていない人が、タイムラインを見られるか（[04 タイムライン](04-timeline.md) と共通） |
| AUTH-7 | ユーザーの削除（退会）を作るか。作る場合の、投稿などの扱い |
| AUTH-8 | 管理者の機能が要るか（ふつうは要らない） |
