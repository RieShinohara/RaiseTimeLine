# 機能定義書 08：ユーザー検索

> **状態：ドラフト（2026-11-13）。実装の反映は 2026-11-22 まで（API。画面は、これから）。** 「【未決】」は、まだ決まっていない点。「【補足】」は、Claude Code が補った提案（ユーザーの確認待ち）。
> 全体の機能は [機能一覧](../features.md) を参照。

## 1. 概要と目的
- フォローしたいユーザーを、**ユーザー名・表示名**で探す機能（講義の内容。表示名は、2026-11-15 に追加）
- 投稿の本文の検索は、作らない（将来の候補。[機能一覧](../features.md)）

## 2. 決まっていること
- 検索の対象は、**ユーザー名と、表示名の両方**（SRCH-4。2026-11-15 決定。日本語の表示名でも探せる）。大文字小文字は区別しない部分一致（SRCH-1）は、両方に適用する
- **ログインしていなくても、使える**（2026-11-14 ユーザー決定）
- **一致のしかたは、部分一致**（名前のどこかに、入力した文字があればよい）。**大文字小文字は区別しない**（SRCH-1。2026-11-13 決定）
- **検索の入力欄は、全画面のヘッダーに置く**（どの画面からでも、すぐ検索できる）。結果は、検索結果の画面に表示する（SRCH-3。2026-11-13 決定）
- 【補足】結果の並び順は、ユーザー名の順。表示は、20 件まで（SRCH-2。多いときは、条件をしぼってもらう案内を出す）
- 結果から、ユーザーを選ぶと、そのユーザーのプロフィールへ移動する（[07](07-profile-follow.md)）
- 一致するユーザーがいないときは、「見つかりません」と表示する（【補足】）

## 3. 操作の流れ（ユースケース）

### UC-12: ユーザーを検索する
- 事前条件：なし（ログインなしでも使える。AUTH-6。2026-11-14 ユーザー決定）
- 基本の流れ：
  1. 検索の欄に、ユーザー名（の一部）を入力して、検索する
  2. 一致したユーザーの一覧が表示される（ユーザー名、アイコン、自己紹介の一部。【補足】）
  3. ユーザーを選ぶと、プロフィールが開く（UC-9）
- 例外の流れ：
  - 一致するユーザーがいないときは、「見つかりません」と表示する
  - 入力が空のまま検索したときは、検索しない（【補足】）

## 4. 画面に出るもの

## 5. 使うデータと API
- USER（ユーザー名・表示名）。[データ設計](../database-design.md) 2.1
- **API**（2026-11-22。Issue #157。画面は、別の Issue で作る）：

| Method | Path | 説明 |
|---|---|---|
| GET | `/api/users?q={入力}&size=20` | ユーザー名か表示名に、`q` を含む人（部分一致・大文字小文字を区別しない）。**ログイン不要**。**ユーザー名の順**（大文字小文字を無視。同じなら id）。`size` は 1〜50（既定 20）。応答は `{ users, hasNext }`（フォロー・フォロワーの一覧と同じ形。`id`・`username`・`displayName`・`bio`・`followedByMe`。**メールは含めない**） |

- **`q` の条件**：前後の空白（全角も）を取る。**空・空白だけは 400**、**50 文字を超えると 400**（表示名の上限と同じ）。`size` が範囲外も 400。該当なしは、200 で空の一覧
- **宛先は `/api/users?q=`**（`/api/users/search?q=` にしなかった理由：`/api/users/{username}` と同じ形になり、ユーザー名「search」の人のプロフィールと区別がつかなくなる）
- **`LIKE` の記号を、文字として扱う**：SQL の `LIKE` では `%`（何文字でも）と `_`（1 文字）が特別な意味を持つ。ユーザー名には `_` が使えるので、そのままだと「a_b」が「axb」にも当てはまる。入力の中の `\`・`%`・`_` には、前に `\` を付けて、ただの文字として探す（`ESCAPE '\'`）。値は `#{}` で渡す（SQL インジェクションは、起きない）
- SQL は、ログイン中が 2 回（検索 1 ＋ フォロー済みの確認 1〔まとめて〕）、ログインなしが 1 回。人数が増えても、同じ
- 詳しくは [ノート 29](../../notes/29-user-search-api.md)
