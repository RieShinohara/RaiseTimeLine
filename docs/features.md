# 機能一覧

RaiseTimeLine の機能の概要（入口）。機能が多く、1 つ 1 つが重いため、**詳細は、機能ごとの機能定義書（[features/](features/)）に分けている**。

> **状態：ドラフト（2026-11-13）。** 「【未決】」は、まだ決まっていない点。「【補足】」は、Claude Code が補った提案（ユーザーの確認待ち）。

## 1. 最初に作る機能（一覧）

| # | 機能 | 概要 | 機能定義書 |
|---|---|---|---|
| 01 | 認証 | ユーザー登録（ログインとは別の画面）、ログイン、ログアウト。JWT ＋ Spring Security。**見るだけは、ログインなしでもできる** | [01-auth.md](features/01-auth.md) |
| 02 | 投稿 | 280 文字までの投稿、**編集**、**削除**（自分の投稿だけ） | [02-post.md](features/02-post.md) |
| 03 | 画像 | 投稿の画像、アイコン画像（保存先は AWS S3） | [03-image.md](features/03-image.md) |
| 04 | タイムライン | **全体**と**フォロー中**の 2 種類 | [04-timeline.md](features/04-timeline.md) |
| 05 | コメント | 投稿へのコメント。**数が分かる**。**投稿した本人も、自分の投稿にできる** | [05-comment.md](features/05-comment.md) |
| 06 | いいね | 投稿へのいいね。**数が分かる**。**投稿した本人も、自分の投稿にできる** | [06-like.md](features/06-like.md) |
| 07 | プロフィール・フォロー | ユーザー名・表示名・アイコン・自己紹介、フォロー・フォロワー。ユーザー名からプロフィールへ移動して、フォロー | [07-profile-follow.md](features/07-profile-follow.md) |
| 08 | ユーザー検索 | ユーザー名で検索 | [08-user-search.md](features/08-user-search.md) |

- 操作の流れ（ユースケース UC-1〜16）は、各機能定義書にある。一覧は [ユースケース](use-cases.md)
- 機能どうしのつながり：認証（01）は、すべての土台。画像（03）は、投稿（02）とプロフィール（07）が使う。タイムライン（04）は、投稿（02）とフォロー（07）を使う

機能をまたぐ決定（X-2。2026-11-15 に決定）：
- **進め方**：機能ごとに、バックエンドの API → 画面の順（別々の Issue・PR）。ただし、認証だけは、先生にそろえて、バックエンドをまとめて先に作る
- **作る順番**：①環境構築（MUI・MyBatis の版の確認、Docker、CI）②認証 ③投稿・全体のタイムライン ④プロフィール・フォロー・「フォロー中」 ⑤いいね・コメント ⑥画像（S3）と、AWS へのデプロイ ⑦検索
- ローカルでは、S3 の代わりの保存先が要る。画像の段階で決める

機能をまたぐ決定（インフラ。2026-11-15 に決定。詳しくは [インフラ構成](infrastructure.md)）：
- **X-1**：ALB を使う（使い終わったら `destroy`）。NAT Gateway は使わない。Subnet は Public 2・Private 2（AZ を分ける）。EC2・RDS は 1 台ずつ。`0.0.0.0/0` を入口に書くのは、ALB の 80 番だけ
- **X-3**：学習中は HTTP のまま。本物のパスワード・個人情報は入れない。講義で HTTPS が出たら、相談して切り替える

機能をまたぐ未決：なし
