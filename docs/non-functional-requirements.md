# 非機能要件

機能そのものではなく、「どのような条件で動くか」「どのくらいの品質か」を定める。
機能については [機能一覧](features.md) を参照。

> **状態：ドラフト（2026-11-13）。** 数値は、TaskManagement を参考にした仮の値（【補足】）。「【未決】」は、まだ決まっていない点。

## 1. 動作環境
- 開発：Windows、Chrome ブラウザ
- 利用：Chrome ブラウザ（【補足】他のブラウザは、動作の保証をしない）
- 公開先：AWS（EC2・RDS・ALB・S3）。構成は、[インフラ構成](infrastructure.md) のとおり
- **学習用**なので、使い終わったら、AWS の物は `terraform destroy` で消す（費用の管理）

## 2. データの保存
- 投稿・コメント・いいね・ユーザーなどのデータは、データベース（PostgreSQL）に保存する
- 画像（投稿の画像、アイコン画像）は、AWS S3 に保存し、データベースには、場所（キー）だけを保存する
- 操作の内容は、その都度、自動で保存される
- ブラウザを閉じても、データが消えない

## 3. 性能・容量（【補足】仮の値）
- 通常：ユーザー数 数十人、投稿数 数千件で、操作に支障がないこと
- タイムラインの表示：1 回に読み込む件数を絞り、下へ進むと続きを読み込む（1 回 20 件。【補足】仮の値）
- 画像：1 枚あたりの上限は 5MB。種類は JPEG・PNG・GIF・WebP。縮小はしない（IMG-3。2026-11-15 決定）
- 文字数：投稿 280 文字まで。自己紹介 160 文字まで（【補足】）。ユーザー名 2〜30 文字、表示名 50 文字まで、メールアドレス 255 文字まで（AUTH-4）

## 4. セキュリティ（複数のユーザーが使う、公開リポジトリ・公開サービス。重要）
- **パスワードは、そのままの形で保存しない**（ハッシュ化。**BCrypt**。2026-11-14）
- 認証は、**JWT ＋ Spring Security**。札は 2 種類：**アクセストークン 15 分、リフレッシュトークン 7 日**（リフレッシュは、DB に保存し、ログアウトで無効にできる）。**JWT の署名の鍵は、リポジトリに入れない**（[01 認証](features/01-auth.md) 3.5）
- 画面側は、札を **localStorage** に保存する（弱点：悪いスクリプトを埋め込まれると、読まれる）。**XSS を起こさないことが、守りの土台**
- リフレッシュトークンの値は、ログ・文書に出さない
- **見るだけの機能は、ログインなしで使える**（2026-11-14 決定）。そのぶん、**どの API の応答にも、メールアドレスを含めない**
- **ログインした本人だけが、自分の投稿を、編集・削除できる**（他の人の分は、サーバー側で必ず拒否する）
- 認証が必要な操作（投稿・コメント・いいね・フォロー・編集・削除、「フォロー中」の表示）は、ログインしていないと、できない
- 入力の確認は、画面側と**サーバー側の両方**で行う（文字数、画像の種類・サイズなど）
- ユーザーが入力した文字を表示するときは、スクリプトの埋め込みなどの攻撃を防ぐ（【補足】React の標準の対策に頼り、HTML をそのまま出す書き方は、しない）
- 画像のアップロード：ファイルの種類とサイズを、サーバー側で確認する。拡張子だけでなく、ファイルの中身でも確認する（IMG-3）
- 画像の公開：画像用の S3 バケットだけを公開し、ファイル名は推測できない名前（UUID）にする（IMG-1）
- **通信**：学習中は HTTP のまま（X-3。2026-11-15 決定）。**本物のパスワード・個人情報は入れない**。あとで HTTPS にできる形にする（講義で出たら、相談して切り替える）。[インフラ構成](infrastructure.md) 7
- **AWS の入口**：EC2・RDS の入口は、自分の IP か、ロードバランサーのグループだけ。`0.0.0.0/0` を入口に書くのは、ロードバランサーだけ（CLAUDE.md の約束）
- RDS は、インターネットから直接つながらないようにする（Private Subnet）。S3 は、画像用のバケットだけ公開し（読むだけ）、書き込み・削除は EC2 の IAM ロールだけができる（IMG-1）
- 秘密（パスワード、キー、AWS のアクセスキー）は、リポジトリに入れない（CLAUDE.md の 4）
- ログインの失敗を繰り返す攻撃への対策（回数の制限）：今回は作らない（AUTH-5。2026-11-15 に仮決め）

## 5. 個人情報・公開リポジトリ
- サンプルデータ（ユーザー名、自己紹介、投稿、画像）は、**すべて架空**にする。実在の人名・会社名・本物の顔写真を、入れない
- ユーザーがアップロードした画像を、リポジトリに入れない。テストの画像は、テストコードの中で作る
- 集める個人情報は、最小限にする。【暫定】集めるのは、**メールアドレス**（ログインに使う）と、パスワード（ハッシュ化）だけ（2026-11-14。講義のプロトタイプで確認）
- **メールアドレスは、他のユーザーに見せない**（プロフィール・投稿・コメント・検索・いいね一覧・フォロー一覧・API の応答に、含めない。【補足】）
- **サンプルデータのメールアドレスは、`@example.com` などの、実在しない形だけ**にする。実在のアドレスを、コード・文書・テスト・画面の録画に、入れない
- ログ（記録）に、メールアドレスとパスワードを、そのまま出さない（【補足】）
- DB の中身・書き出したファイルを、コミットしない

## 6. 使いやすさ
- 使用頻度の高い操作（投稿、いいね、コメント、フォロー）は、少ない操作回数でできること
- 取り返しのつかない操作（投稿の削除、アカウントの削除など）は、実行前に確認メッセージを表示する
- 入力エラー（文字数の超過など）は、分かる言葉で、その場で表示する
- 文字数は、入力中に、残りが分かる（【補足】280 文字の残り）
- 見た目の調整は、機能がそろってからでよい（CLAUDE.md の 3.8）

## 7. 権利
- 画像や文章は、権利が明らかな物だけを使う。出典とライセンスは、`CREDITS.md` に書く
- アイコン画像の初期値（未設定のとき）は、自分で作った簡単な図にする（【補足】）

## 8. 運用・費用（【補足】）
- AWS の費用がかかる物は、使い終わったら消す。ロードバランサー・NAT Gateway は、特に注意する
- NAT Gateway は使わない（X-1。2026-11-15 決定）
