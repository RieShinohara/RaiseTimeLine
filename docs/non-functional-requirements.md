# 非機能要件

機能そのものではなく、「どのような条件で動くか」「どのくらいの品質か」を定める。
機能については [機能一覧](functional-requirements.md) を参照。

> **状態：ドラフト（2026-11-13）。** 数値は、TaskManagement を参考にした仮の値（【補足】）。「【未決】」は、まだ決まっていない点。

## 1. 動作環境
- 開発：Windows、Chrome ブラウザ
- 利用：Chrome ブラウザ（【補足】他のブラウザは、動作の保証をしない）
- 公開先：AWS（EC2・RDS・S3。ロードバランサーは【未決】）。構成は、これから作る構成図で決める
- **学習用**なので、使い終わったら、AWS の物は `terraform destroy` で消す（費用の管理）

## 2. データの保存
- 投稿・コメント・いいね・ユーザーなどのデータは、データベース（PostgreSQL）に保存する
- 画像（投稿の画像、アイコン画像）は、AWS S3 に保存し、データベースには、場所（キー）だけを保存する
- 操作の内容は、その都度、自動で保存される
- ブラウザを閉じても、データが消えない

## 3. 性能・容量（【補足】仮の値）
- 通常：ユーザー数 数十人、投稿数 数千件で、操作に支障がないこと
- タイムラインの表示：1 回に表示する件数を、決めた数に絞る（【未決】件数）
- 画像：1 枚あたりの上限は【未決】（目安：5MB。種類は JPEG・PNG など）
- 文字数：投稿 280 文字まで。ユーザー名・自己紹介の上限は【未決】

## 4. セキュリティ（複数のユーザーが使う、公開リポジトリ・公開サービス。重要）
- **パスワードは、そのままの形で保存しない**（ハッシュ化。方式は、技術スタックで決める）
- **ログインした本人だけが、自分の投稿を、編集・削除できる**（他の人の分は、サーバー側で必ず拒否する）
- 認証が必要な操作（投稿・コメント・いいね・フォロー・編集・削除）は、ログインしていないと、できない
- 入力の確認は、画面側と**サーバー側の両方**で行う（文字数、画像の種類・サイズなど）
- ユーザーが入力した文字を表示するときは、スクリプトの埋め込みなどの攻撃を防ぐ（【補足】React の標準の対策に頼り、HTML をそのまま出す書き方は、しない）
- 画像のアップロード：ファイルの種類とサイズを、サーバー側で確認する
- **通信**：公開するときは、HTTPS にする（【未決】ドメイン・証明書をどうするか。学習の範囲）
- **AWS の入口**：EC2・RDS の入口は、自分の IP か、ロードバランサーのグループだけ。`0.0.0.0/0` を入口に書くのは、ロードバランサーだけ（CLAUDE.md の約束）
- RDS・S3 は、インターネットから直接つながらないようにする（【未決】S3 の公開・非公開の方式）
- 秘密（パスワード、キー、AWS のアクセスキー）は、リポジトリに入れない（CLAUDE.md の 4）
- 【未決】ログインの失敗を繰り返す攻撃への対策（回数の制限）。学習の範囲で、やるか

## 5. 個人情報・公開リポジトリ
- サンプルデータ（ユーザー名、自己紹介、投稿、画像）は、**すべて架空**にする。実在の人名・会社名・本物の顔写真を、入れない
- ユーザーがアップロードした画像を、リポジトリに入れない。テストの画像は、テストコードの中で作る
- 集める個人情報は、最小限にする（【未決】メールアドレスを集めるか）
- DB の中身・書き出したファイルを、コミットしない

## 6. 使いやすさ
- 使用頻度の高い操作（投稿、いいね、コメント、フォロー）は、少ない操作回数でできること
- 取り返しのつかない操作（投稿の削除、アカウントの削除など）は、実行前に確認メッセージを表示する
- 入力エラー（文字数の超過など）は、分かる言葉で、その場で表示する
- 文字数は、入力中に、残りが分かる（【補足】280 文字の残り）
- 見た目の調整は、機能がそろってからでよい（CLAUDE.md の 3.8）

## 7. 権利
- 画像や文章は、権利が明らかな物だけを使う。出典とライセンスは、`CREDITS.md` に書く
- アイコン画像の初期値（未設定のとき）は、自分で作った簡単な図にする（【補足】）

## 8. 運用・費用（【補足】）
- AWS の費用がかかる物は、使い終わったら消す。ロードバランサー・NAT Gateway は、特に注意する
- 【未決】NAT Gateway を使うか（費用が大きい。使わない構成にできるか、構成図で検討）
